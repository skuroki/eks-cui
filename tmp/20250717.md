# Apple M4 MacBook対応作業計画

## 現状の問題
- Intel MacBookで動作していたeks-cuiツールをApple M4 MacBookで実行する際、chrome/chromiumが動作しない
- aws-azure-loginがPuppeteerを使用してブラウザ自動操作を行うため、chromiumの起動失敗により認証が完了しない
- 現在のDockerfileはx86_64アーキテクチャ前提で構築されている

## 解決方針（teian.md A案ベース）
ARM64ネイティブDockerイメージでChromiumをインストールし、Puppeteerにパスを明示的に渡す方式を採用

## 作業項目

### 1. Dockerfileの修正
- [ ] ベースイメージをARM64ネイティブに変更（`--platform=linux/arm64`）
- [ ] Google Chrome StableからChromiumパッケージに変更
- [ ] Puppeteer環境変数の設定
  - `PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true`
  - `PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium`
- [ ] ARM64対応のAWS CLI v2インストールコマンド修正
- [ ] ARM64対応のeksctlインストールコマンド修正

### 2. docker-compose.ymlの修正
- [ ] buildセクションにplatform指定を追加
- [ ] Chrome起動時のサンドボックス無効化フラグ追加（必要に応じて）

### 3. 環境変数の調整
- [ ] aws-azure-login実行時のChrome起動オプション調整
- [ ] Puppeteer設定の環境変数追加

### 4. 動作確認

## 実装詳細

### Dockerfile変更点
1. ベースイメージ変更: `FROM --platform=linux/arm64 ubuntu:22.04`
2. Google Chrome削除、Chromiumインストール追加
3. AWS CLI、eksctlのARM64版ダウンロードURL変更
4. Puppeteer環境変数設定

### docker-compose.yml変更点
1. platformフィールド追加
2. Chrome実行時フラグの環境変数追加

## 注意事項
- ARM64環境でのパフォーマンステストが必要
- 既存の.envファイルやAWS認証設定に影響しないよう注意
- ホスト側のDocker Desktop設定（Rosetta使用有無）の確認

- 既存のワークフローが継続して使用できる
